# Integration contract

Internal implementation agreement. All JSON keys use snake_case. No em dash characters in authored files. Browser requests use credentials: include. REST routes under /api; MCP at /mcp. Error responses use {"detail":"human readable message"}. No fake successful responses.

## Identity

POST /api/auth/login {email,password} -> {user:{id,email,name,role},csrf_token}. Session in HttpOnly SameSite=Lax cookie. GET /api/auth/me same result. POST /api/auth/logout. Mutations after login use X-CSRF-Token. GET /api/health -> {status,chat_configured,store_url,gateway_url}. Passwords never returned.

POST /api/auth/accept-invite {token,name,password} -> {user,csrf_token}, with a fresh session cookie for the invited account. Successful acceptance and password login revoke only the browser session they replace. Invalid or used invitations leave the current session unchanged. GET /api/invites/{token} -> {email,role,expires_at}. Browser tabs refresh identity after an account change and clear the previous account's workspace state.

## Registry

GET /api/servers -> array of {id,name,slug,url,enabled,status,last_error,last_checked_at,tools:[{name,description,inputSchema,permission}]}.
POST /api/servers {name,slug,url,auth_type:"none"|"bearer"|"header",credential?,header_name?,enabled:true} -> server.
PATCH /api/servers/{id} same editable fields (slug immutable). Blank/omitted credential preserves current credential; explicit clear_credential=true removes it. DELETE /api/servers/{id}. POST /api/servers/{id}/refresh.
Only admins mutate registry. All users may see non-secret server summaries. Never return credential values. Tool permission is "read" or "write"; unknown newly registered tools default admin-only. PATCH /api/servers/{id}/tools/permissions {permissions:{original_tool_name:"read"|"write"}} is admin only.

## Keys and team

GET /api/keys -> array of {id,name,prefix,user_id,created_at,last_used_at,revoked_at} (own keys; admins all).
POST /api/keys {name,user_id?} -> {key,record}. Key shown once. DELETE /api/keys/{id} revokes.
GET /api/members -> array {id,name,email,role,created_at,active}. PATCH /api/members/{id} {role?,active?}.
GET /api/invites -> array {id,email,role,expires_at,accepted_at}. POST /api/invites {email,role} -> {invite_url,...}. Admin only. Copy invitation links, no email provider.

## Audit and chat

GET /api/audit?limit=50&offset=0&outcome=&server_id=&user_id= -> {items:[{id,user_id,user_name,user_email,server_name,tool_name,timestamp,duration_ms,outcome,error,request_id}],total}. Members see own records; admin sees all.
POST /api/chat {messages:[{role:"user"|"assistant",content:string}]} -> {message:string,tool_calls:[{name,arguments,result,is_error,duration_ms}],confirmation?:{id,summary,tool_name,arguments}}. No streaming required for first implementation. Pending write proposals require POST /api/chat/confirm {id,approve:boolean}, returning same shape. Server holds confirmation tied to session/user and rechecks permission. All actual tool calls use MCP HTTP gateway with session-derived credential. Return 503 with useful error when Gemini key missing. Never fake an LLM result.

## Kubernetes/environment contract

Backend port 8000, command uvicorn backend.app:app --host 0.0.0.0 --port 8000. Upstreams port 8001, command python -m upstreams.server, MCP /mcp. UPSTREAM_KIND = woo|policies|shipping, UPSTREAM_TOKEN required, WOO_URL and WOO_KEY and WOO_SECRET for woo. Upstream /health/live and /health/ready. Backend /health/live and /health/ready.

Backend DATABASE_URL (postgresql+psycopg://...), SESSION_SECRET, BOOTSTRAP_ADMIN_EMAIL, BOOTSTRAP_ADMIN_PASSWORD, BOOTSTRAP_ADMIN_NAME, GEMINI_API_KEY (optional until user supplies), GEMINI_MODEL (default gemini-3.1-flash-lite), STORE_URL (public), GATEWAY_URL (public), INTERNAL_GATEWAY_URL (http://127.0.0.1:8000/mcp), ALLOWED_ORIGINS (comma-separated), SECRET_BACKEND=kubernetes|file. File mode strictly local dev; .secrets/upstreams.json. UPSTREAM_CREDENTIAL_SECRET=commerce-upstream-credentials, POD_NAMESPACE. ALLOWED_INTERNAL_HOSTS comma-separated exact service DNS names. BOOTSTRAP_SERVERS_JSON contains [{name,slug,url,credential_key,read_tools:[]}]; gateway credentials in the mutable K8s Secret keyed by slug. Upstream pods use separate fixed service-token fields in the application Secret. Bootstrap runs once, records its completion in PostgreSQL, and never recreates connections deleted by an administrator.

All credentials generated by scripts, no checked-in credentials. Local URLs http://console.localhost:8080 and http://store.localhost:8080 through Ingress (loopback .localhost names); /mcp under console host. Docker image commerce-console:dev for backend and upstreams; commerce-dashboard:dev for frontend; commerce-wordpress:dev for store. All services ClusterIP, only dashboard/backend and store have Ingress. Requests, limits, startup/readiness/liveness, PVCs and network policies included.
